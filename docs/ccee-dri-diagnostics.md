# DRI diagnostics and source discovery

The DRI connector still rejects different disclosure objects sharing one event code. A bounded diagnostic now identifies the event code, the hashes of both objects and up to sixteen changed metadata paths. Values, authentication headers and raw XML are excluded. Original row counts, response hashes and transaction IDs retain their existing behavior. Within-page and cross-page conflicts use the same diagnostic; successful normalized rows never include raw disclosure metadata.

Migration `20261243_ccee_dri_diagnostics.sql` wraps the existing finish function. It validates and removes the additive diagnostic before delegating to the strict original metrics/lease/authorization logic, then appends a private `READ_DIAGNOSTIC` event in the same transaction. Existing audit events and failed-job results remain untouched. The former finish implementation cannot be called by `service_role` directly. No new table or human grant is introduced.

The private `ccee_dri_diagnostic_read` function verifies the organization actor and live representation before returning selected job metadata, provenance and the bounded diagnostic. The DRI detail and automatic-service panels distinguish transport/provider refusal, local parser failure, unavailable source selection and financial mapping. The latest job is shown separately from historical policy errors. Empty successful results are disclosed as absence in that query scope, never as zero costs or a global API outage.

Source discovery must follow the provider's event → report/version → frame → result chain. Events for liquidation, reserve energy/capacity, nuclear quotas, votes/contribution, guarantees and penalties are separate from accounting. Neither names in an Excel performance report nor the presence of an event prove availability of a specific result for a represented profile. Never invent numeric report/frame IDs. Public announcements describe candidate report families but do not replace the live scoped catalog.

No new financial mapping is activated by this diagnostic. In particular, do not sum accounting effects, consolidated MCP and individual settlements indiscriminately, treat guarantees as ordinary energy charges, infer payment from a liquidation result, or distribute agent-level totals across units without an authorized allocation. New mappings require verified columns, signs, version, accounting/disbursement competence, scope and overlap rules. Existing financial approvals and published closings remain unchanged.

Tests cover bounded/redacted metadata and actual parser errors, unchanged conflict protection, database lease/scope and append-only audit, RPC privileges and readable UI/provenance in Brasília time. No paid OCR/IA, contract transmission or certificate change is required.
