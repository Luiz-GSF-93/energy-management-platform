# Published client forecasts and same-month averages

The portal reads only validated and published snapshots of its live external consulta membership's exclusive customer. Customer and unit IDs are not request inputs. Existing licenses and report permission remain mandatory. Platform sessions, inactive memberships, moved roles, revoked permissions and inactive customers are denied. The service-only RPC keeps the forecast tables inaccessible directly and returns at most the latest published version per unit/cutoff, for active units. Draft and validated-only versions never replace a publication. The HTTP projection verifies the full snapshot hash and excludes OCR evidence, documents, coordinates, premise notes, sources and internal review text.

The shared chart distinguishes measured invoice history from future planning, shows the selected method and states whether NASA temperature was queried, applied or unavailable. Client publication is separate from backoffice validation; this change publishes no existing version.

Formula consumption-forecast/1.2 replaces the mean candidate with an average of daily consumption for the target month in prior years when at least two validated observations exist. Otherwise it averages the available historical daily consumption. Billed days normalize historical readings; calendar days scale the future month. Each monthly fallback records its basis and source months in the immutable snapshot. Other existing candidates remain selected by chronological MAE; this policy applies when the mean candidate is selected. Each test origin uses only its training subset. Climate formula 1.3 compares against the updated candidates using the existing acceptance gates. Climate forecasts remove mean-only basis annotations. Existing forecasts retain their versions and hashes; only new snapshots use the rule.

Apply the two additive migrations before enabling the new release. The formula migration changes only the accepted formula identifiers in the existing prepare function; no publication, source or permission check is changed. No auth, CCEE, financial or document service is modified. Confirm schema reload and service-only grants, then homologate using an existing consulta account linked to a customer with a manually published forecast.
