# F1.4i.1 — License Effective Read Foundation

## Scope

This checkpoint introduces the minimum organization-scoped backend read
foundation for effective licenses.

Implemented:

- dedicated LicensesModule;
- GET /licenses/effective;
- ORGANIZATION_LICENSES_VIEW permission enforcement;
- organization scope derived exclusively from validated TenantContext;
- backend effective-license resolution;
- explicit fail-closed handling for database errors and ambiguous state;
- inclusive start/end date semantics;
- focused controller and service specifications;
- AppModule registration.

Not implemented in this checkpoint:

- license creation;
- license update;
- lifecycle mutation;
- hard deletion;
- mutation audit;
- entitlement administration;
- frontend license management;
- role-permission assignment;
- Platform Admin bypass;
- RLS policy changes.

## Effective-license contract

A license is effective only when all applicable conditions hold:

- organization_id matches the validated tenant organization;
- active is true;
- normalized status is active;
- start_date is present;
- start_date is not after the evaluation date;
- end_date is null or not before the evaluation date.

start_date and end_date boundaries are inclusive.

renewal_date is preserved as a commercial field and is not interpreted as
the validity end date.

## Fail-closed behavior

The resolver returns null when no effective license exists.

Database lookup failure does not become null and raises an internal error.

More than one effective candidate is treated as an ambiguous state and raises
an internal error.

A null result therefore represents absence of an effective license, not
authorization to a licensed capability.

## Tenant isolation and authorization

The controller accepts no organization identifier from the client payload.

The organization identifier is obtained from TenantContext and passed to the
service.

The database query is explicitly scoped by organization_id.

The endpoint requires the existing ORGANIZATION_LICENSES_VIEW permission.

No permission aliases or automatic role grants were introduced.
