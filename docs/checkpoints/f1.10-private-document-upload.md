# F1.10 — Private document upload and download

POST /documents/upload accepts multipart file plus customerId, consumerUnitId, documentType, referenceMonth (YYYY-MM-01), optional energyContractId and description. Permission and license checks remain mandatory. Files are limited to 10 MiB and PDF/JPEG/PNG. The server identifies signatures, compares declared MIME, calculates SHA-256 and size from bytes, generates a random tenant/unit object key and stores in energy-documents-private with upsert disabled. Signature validation is not antivirus or a full PDF/image parser; OCR and human validation remain pending.

The bucket is private with matching size/MIME restrictions. A restrictive storage.objects policy denies direct anon/authenticated access to this bucket, even if other permissive policies exist; service_role remains server-side. GET /documents/:id/download checks license, permission, tenant and verified storage metadata before producing a 60-second attachment URL. Legacy metadata cannot generate download links.

A trigger serializes document inserts per organization, locks the single active license, checks the document capability and remaining documents_limit, increments documents_used and sets upload_license_id in the insert transaction. Failed/duplicate inserts roll back the counter. No existing usage values are reset or recalculated; renewal/reset policy is unchanged. New file_verified, storage_bucket and file_verified_at columns distinguish actual files from previous metadata.

Storage/SQL are separate services. Confirmed database rejections remove only the attempt's random object. Lost insert responses are checked for a committed row. An indeterminate outcome or failed cleanup returns an explicit administrative reconciliation error and logs the object key; it never removes bytes potentially referenced by a committed document. Automatic orphan reconciliation/retry is future work. Metadata POST remains available but cannot claim verified storage fields.

The Documents page provides customer/unit/period/type selection, upload feedback, listing and authorized download; context changes remount tenant state. It requires existing customer/unit read permissions for the selectors. FormData support preserves JSON callers. The menu follows document-view permission.

Validation: full backend tests including real multipart HTTP limits/permission checks, file handling and compensation cases; frontend build/lint; isolated SQL fixture for migration repeatability, quota/duplicates and restrictive storage policy. Production bucket configuration uses backend/scripts/configure-document-storage.cjs with existing server environment and never prints credentials. Apply SQL and configure bucket before merge. Production rollout status is recorded in the release report.
