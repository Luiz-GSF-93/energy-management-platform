# F1.2.3 — Organization Membership Deactivation Closeout

## Status

CLOSED — implementation validated and published.

## Objective

Add organization-scoped user deactivation to the administrative user
lifecycle without deleting the authentication identity, modifying the user
profile, creating global role assignments, or crossing tenant boundaries.

The operation deactivates only the target `organization_members` membership
inside the actor's validated active organization.

## Architecture contract

The implementation preserves the established identity and authorization model:

- `auth.users` remains the authentication identity authority.
- `user_profiles` remains profile data and active-organization pointer data.
- `organization_members` remains the organization membership authority.
- organization membership status is changed from `active` to `inactive`.
- no hard deletion of the authentication identity is performed.
- no mutation of `user_profiles` is performed.
- no mutation of `user_roles` is performed.
- no Platform Admin bypass was introduced.
- organization scope comes from validated tenant context.
- the target organization is never accepted from request body input.

## Endpoint

Administrative deactivation is exposed as:

`DELETE /admin/users/:userId`

Required permission:

`ORGANIZATION_USERS_DELETE`

The controller forwards:

- target user ID;
- actor user ID from tenant context;
- organization ID from tenant context;
- request IP when available;
- user-agent when available.

The endpoint does not accept a request body for organization selection or
membership status selection.

## Service behavior

The service:

1. blocks self-deactivation before database access;
2. resolves exactly one active membership for the target user in the current
   organization;
3. fails closed on missing, duplicate, malformed, or failed membership lookup;
4. performs a compare-and-set membership update from `active` to `inactive`;
5. scopes the mutation by target user, current organization, and previous
   `active` status;
6. requires exactly one updated membership row;
7. validates the returned membership after mutation;
8. writes persistent audit only after a confirmed membership mutation.

The operation does not delete the membership record.

## Persistent audit

F1.2.3a introduced:

`AuditService.logUserMembershipDeactivation(...)`

Audit action:

`DEACTIVATE_USER_MEMBERSHIP`

Audit resource:

`organization_membership`

The persistent audit records:

- actor user ID;
- organization ID;
- target user ID;
- membership ID;
- before status `active`;
- after status `inactive`;
- IP address when available;
- user-agent when available;
- success status;
- timestamp.

Audit persistence is fail-closed.

## Compensation behavior

If the membership mutation succeeds but persistent audit fails, the service
attempts a guarded compensating rollback.

The rollback is scoped by:

- target user;
- current organization;
- current `inactive` status.

The rollback restores the previous `active` status only when the expected
post-mutation state is still present.

A confirmed rollback reports the operation as reverted.

An unconfirmed rollback is treated as a CRITICAL integrity failure rather than
reporting success.

This prevents an audit failure from silently leaving an unaudited membership
deactivation.

## Security boundaries

The implementation introduces no mutation of:

- `auth.users`;
- `user_profiles`;
- `user_roles`;
- database schema or migrations;
- RLS policies;
- package dependencies;
- TypeScript configuration.

It introduces no `org_default` dependency.

Tenant isolation remains enforced by the validated organization context and by
organization-scoped membership lookup, mutation, and rollback.

## Closeout decision

F1.2.3 is accepted as the organization-membership deactivation foundation.

The administrative delete semantic for this phase is membership deactivation,
not authentication identity deletion.

Future lifecycle work must preserve this distinction unless a separately
designed, audited, and explicitly approved hard-delete workflow is introduced.
