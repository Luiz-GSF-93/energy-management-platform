## Authorization and tenancy model

The implementation follows the approved F1.2 architecture:

1. `organization_members` is the organization-access authority.
2. The current organization comes from the validated organization context.
3. User profiles do not establish organization visibility.
4. `user_roles` is not used as an organization-role fallback.
5. `auth.users` is not queried by these endpoints.
6. Platform scope is not introduced into these endpoints.

List composition follows:

`organization_members scoped to current organization -> authorized user_ids -> user_profiles bounded to those IDs -> response composition`

Single-user read follows:

`organization_members scoped by target user + current organization -> user_profile -> response composition`

A direct `organization_members -> user_profiles` PostgREST relationship was deliberately not introduced because live discovery showed that relationship is not available.

## Administrative visibility

Read endpoints intentionally do not filter memberships to `status = active`.

This allows administrative visibility of membership state and supports the planned lifecycle/deactivation flow.

The response includes `membershipStatus`.

Operations that require an active membership remain independently responsible for enforcing that requirement.

The existing `updateAffiliation` behavior was preserved byte-for-byte during F1.2.1.

## Response surface

The administrative read model exposes:

- `userId`
- `email`
- `name`
- `affiliationType`
- `membershipStatus`
- `role.id`
- `role.name`
- `invitedAt`
- `acceptedAt`

It does not intentionally expose:

- `user_profiles.organization_id`
- `user_profiles.role_id`
- raw role permissions
- role organization/scope
- auth metadata
- tokens

## Integrity behavior

The implementation fails closed for inconsistent data, including:

- missing profile for an authorized membership
- duplicate profile
- unexpected profile outside the authorized ID set
- missing role
- null membership role
- role ID mismatch
- role organization mismatch
- global role in organization membership
- invalid affiliation classification
- duplicate membership on single-user lookup
- database query errors

An empty organization membership set returns an empty list without querying profiles.
