boundary.

were entered.

mutation.

## Controlled target selection

Production validation was restricted to the Organization created specifically
for P2.2b production validation.

The Organizations list returned HTTP 200.

Exactly one Organization matched the controlled validation name.

The target identifier was present but was not printed.

The gate would stop without mutation if:

- no matching Organization existed;
- more than one matching Organization existed;
- the Organization was already in the expected P2.2c state;
- the pre-Update state differed from the state established by P2.2b.

The expected pre-Update state was confirmed before mutation.

## Controlled partial Update

Exactly one intentional Organization Update was performed.

The request used:

`PATCH /api/v1/admin/organizations/:id`

Only the description field was supplied by the controlled validation.

The request returned HTTP 200.

The Update response contract was valid.

The Organization identifier remained unchanged.

The Organization name remained unchanged.

The description matched the controlled P2.2c validation value.

This validated partial PATCH behavior without changing the validation
Organization identity.

## Readback validation

After Update, the target identifier was used internally to read the resulting
Organization.

`GET /api/v1/admin/organizations/:id` returned HTTP 200.

The readback contract was valid.

The returned Organization preserved the expected identifier and name and
contained the updated description.

This confirmed persistence through the existing Organizations read contract.
