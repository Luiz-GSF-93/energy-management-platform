## Problem resolved

Customers authorization was coupled to the Contracts permission domain.

Customers is an independent resource with its own controller, service,
persistence table, routes, DTOs, tenant filtering, and domain relationships.

The legacy mapping reused organization.contracts.* permissions.

## Dedicated permission catalog

The following permissions were introduced:

- organization.customers.view
- organization.customers.create
- organization.customers.update
- organization.customers.delete

Permission IDs were generated by the database and transported to backend
constants only after database validation.

## Backend wiring

CustomersController now uses only dedicated Customers permissions:

- POST /customers -> ORGANIZATION_CUSTOMERS_CREATE
- GET /customers -> ORGANIZATION_CUSTOMERS_VIEW
- GET /customers/:id -> ORGANIZATION_CUSTOMERS_VIEW
- PUT /customers/:id -> ORGANIZATION_CUSTOMERS_UPDATE
- DELETE /customers/:id -> ORGANIZATION_CUSTOMERS_DELETE

CUSTOMERS_PERMISSIONS now references only the dedicated Customers
permission constants.

No ORGANIZATION_CONTRACTS_* authorization reference remains in the
Customers module.
