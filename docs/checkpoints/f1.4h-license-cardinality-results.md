## Added integrity constraints

### licenses_active_start_date_check

An effective active license must have a non-null `start_date`.

The active predicate is:

`((lower(status::text) = 'active') IS TRUE AND active IS TRUE)`

The check does not make `start_date` globally NOT NULL.

### licenses_active_validity_excl

A GiST exclusion constraint prevents rows from coexisting when all of the
following are true:

- they belong to the same organization;
- both represent effective active licenses;
- their validity date ranges overlap.

Historical and non-active licenses remain outside the exclusion predicate.

No global UNIQUE constraint on `organization_id` was introduced.

## Temporal semantics

`start_date` is the first valid calendar day.

`end_date`, when present, is the last valid calendar day.

A null `end_date` represents open-ended validity.

The approved range representation preserves inclusive contractual date
semantics.

PostgreSQL canonicalization of discrete date ranges was verified before DDL.

Two active licenses conflict if one starts on the same calendar day the other
ends.

They do not conflict when the second starts on the next calendar day.

## Sequential rejection proof

An overlapping active license was rejected with:

- SQLSTATE: `23P01`;
- constraint: `licenses_active_validity_excl`.

An active license with null `start_date` was rejected with:

- SQLSTATE: `23514`;
- constraint: `licenses_active_start_date_check`.

No rows from these tests remained persisted.

## Concurrent transaction proof

Two independent database sessions were used.

Session A inserted an active license and kept the transaction open.

Session B attempted to insert an overlapping active license for the same
organization while Session A was unresolved.

After Session A committed, Session B failed with:

- SQLSTATE: `23P01`;
- constraint: `licenses_active_validity_excl`.

The authoritative result contained only Session A's row.

This proves that conflicting concurrent writes cannot both commit.

## Integrity conclusion

The invariant is now database-backed:

> An organization cannot have overlapping effective active license validity
> periods.

Application read-before-write logic is not relied upon as the concurrency
barrier.

Historical and non-overlapping scheduled licenses remain compatible with the
approved model.
