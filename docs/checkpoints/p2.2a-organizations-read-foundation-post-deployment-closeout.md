## Dual-scope authentication decision

Production now validates both frontend authentication paths.

Organization scope resolves through:

`/api/v1/auth/context`

Global Platform Admin scope resolves through:

1. organization context returns the expected HTTP 403;
2. the frontend falls back to `/api/v1/auth/platform-context`;
3. platform context returns HTTP 200;
4. global permissions become the effective frontend presentation context.

HTTP 401 remains an invalid-session result and is not treated as a
platform-context fallback condition.

The organization and platform authorization scopes remain distinct.

## Organizations read authorization

The production validation confirms the existing backend authorization
boundary.

permission was previously denied the Organizations list with HTTP 403.

The Platform Admin production flow returned HTTP 200 for the Organizations
list.

Frontend permission visibility does not replace backend authorization.
