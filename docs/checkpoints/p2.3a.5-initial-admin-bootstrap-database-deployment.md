## Objective

Record the controlled production execution and postflight validation of the

## Published database boundary

The database boundary was published by:

`ae2a118 — feat(administration): establish initial admin bootstrap database boundary`

The published boundary contains:

- dedicated Platform Administration bootstrap permission;
- exclusive assignment to `admin_platform`;
- atomic first-admin membership RPC;
- per-Organization advisory locking;
- service-role-only execution;
- privileged-function postflight assertions.

## Execution preflight

Before migration execution, production read-only validation confirmed:

- bootstrap permission count was zero;
- bootstrap function count was zero;
- no active `admin_org` membership existed;
- no active `gestor` membership existed.

The database therefore matched the expected pre-installation state.

## Initial execution attempt

An initial SQL Editor execution attempt failed before mutation because the
copied SQL began at the PL/pgSQL `BEGIN` statement rather than at its enclosing
`DO $$` block.

PostgreSQL returned syntax error `42601` at the first `IF`.

The published migration source was not changed to compensate for this copy
error.

The complete published migration was subsequently executed.

## Permission installation

Production postflight confirmed the permission:

`platform.organizations.bootstrap_admin`

with:

- name: `platform.organizations.bootstrap_admin`;
- module: `gestao`;
- resource: `organizations`;
- action: `bootstrap_admin`.

## Permission ownership

Production postflight confirmed that the bootstrap permission is assigned to:

`admin_platform`

with:

`scope = global`

No other role was returned as holding the bootstrap permission.

The permission therefore remains a Platform Administration capability.

## RPC installation

Production postflight confirmed:

`public.bootstrap_initial_organization_admin(text, uuid)`

with identity arguments:

`target_organization_id text, target_user_id uuid`

The RPC remains internal to the backend service-role boundary.

## Security definer validation

Production postflight confirmed:

`security_definer = true`

and:

`search_path=pg_catalog`

The function therefore matches the privileged-function hardening contract
published with the database boundary.

## Effective execution privileges

Production postflight confirmed:

- PUBLIC execute: false;
- anon execute: false;
- authenticated execute: false;
- service_role execute: true.

The RPC is not directly executable through normal browser authentication.

## Bootstrap non-execution invariant

After database boundary installation, production validation queried active
Organization administrative memberships.

No active:

- `admin_org`;
- `gestor`;

membership was returned.

Therefore migration installation did not exercise the bootstrap capability.

No Organization membership mutation was intentionally performed by this
deployment checkpoint.

## Concurrency boundary

The installed RPC uses a transaction-scoped PostgreSQL advisory lock derived
from the target Organization identifier.

The installed function retains the published eligibility checks for:

- target Organization existence and soft-delete state;
- exactly one organization-scoped `admin_org` role;
- absence of active `admin_org`;
- absence of active `gestor`;
- absence of an existing target User membership.

The existing database constraint:

`UNIQUE (user_id, organization_id)`

remains complementary protection for membership uniqueness.
