EnergyOS — 5B — private commercial provisioning kernel

Default OFF: SALES_PROVISIONING_COMMANDS_ENABLED and SALES_PROVISIONING_APPLICATION_ENABLED require exact string true; absence fails closed. No credentials, outgoing HTTP or Asaas operations. Current activation source is sandbox-only: execution rejects it independently of flags. No production evidence adapter is introduced here.

Owner-only platform endpoints /api/v1/admin/sales/provisioning: list/read/preview/prepare/authorize/withdraw/execute. Each handler has the Owner capability; SQL revalidates one active global Owner and locks authority for mutation. No new membership or role is granted. No direct table access for anon/authenticated/service_role; only the private action RPC is granted to service_role. The source/payload helper cannot be called directly by API roles.

The backend reads the immutable proposal, contract and 5A sources. It never copies today's catalog limits or price. Monthly recurring price is distinct from initial total; annual activation is explicitly blocked pending a specific implementation. Requested quantities and package limits remain distinct. Document limit 800 survives catalog changes. Modules come only from frozen scope. Owner enters structured license dates and AI quota and confirms compatibility with the preserved contract. Missing values block preparation. Zero AI quota is not unlimited. Dates and quota are an immutable command complement, never a rewrite of the original proposal/contract.

Command reservation: unique activation, unique organization; no overwrite/upgrade. Withdrawal is terminal and retains reservation/history. Corrections require a separately reviewed new commercial chain rather than rewriting a withdrawn command. Prepared/Authorized are private workflow states, not activation success. UI deliberately offers no real application button in this delivery.

Transactional kernel: fresh source/payload hash and checked activation; production eligibility from trusted source only; global licensing and organization locks; conflict check; existing license governance trigger/resource quotas; INSERT license, audit, result and final event in one transaction. No trigger is disabled. No user/org/invite/payment writes. A failed transaction leaves no applied license, result or success audit. A committed but lost response is recovered by replaying the identical execution request; existing license/audit/payload are checked. Divergent retry, altered license/audit or terminal command requires review; no compensation deletion/retry loop.

Source safety: 5A uses only existing sandbox financial adapters and returns realActivationEligible=false. Therefore a real application cannot pass today. The future production adapter requires separate architecture review, confirmed production evidence, source concurrency guarantees and final authorization. The disposable test replaces the source helper ONLY in its fixture schema to exercise positive transactions; that fixture is not shipped as a production adapter and is never installed in the shared database.

Author names: immutable actor ID/name at event time and separate current name lookup. Missing/current registry unavailable remains explicitly unavailable; no role-name substitution. List pages are 25 rows, filters bounded, details/history modal.
